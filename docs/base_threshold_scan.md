# 大水体漏提的百分位阈值对照

> 本文记录旧幅度假设下的历史实验，不能作为已确认功率ORG的当前基线。旧案例配置已删除；工具仍可通过独立YAML使用。

本实验独立于Otsu。沿用`thres_seg_profiles_q30_20261113`的线性幅度、SNAP Lee、剖面地形掩膜、土地覆盖和面清理参数，关闭历史放宽，只改变Base Q。

## 当前抽样结果

核查主要覆盖景：`BC5-SM-ORG-VV-20250725T135519-002331-000048-00091B-01`。在统一30m网格上，取历史水体最大连通域、116.87°E以西部分作为西库参考；该景覆盖其中24,046个参考像元。该范围是历史参考，不是同期真值。

下表的阈值由行政区内缩略采样估计，覆盖率在30m参考网格计算；正式扫描会使用全部有效像元的精确分位数。

| Base Q | 近似幅度阈值 | 西库参考区通过阈值 | 地形排除后 |
|---|---:|---:|---:|
| 30 | 594 | 26.62% | 26.43% |
| 40 | 815 | 48.19% | 48.00% |
| 50 | 1073 | 68.84% | 68.62% |
| 60 | 1403 | 83.90% | 83.63% |
| 70 | 1867 | 92.86% | 92.56% |
| 80 | 2651 | 97.29% | 96.99% |
| 90 | 4516 | 99.38% | 99.08% |

提高阈值可以恢复大部分西库参考范围。与此同时，Base Q80会把约80%的行政区有效观测像元纳入原始暗侧候选，远不止水库。因此本实验用于判断全局阈值的局限，不能因为水库更完整就认定高Q适合生产。

## 执行

```powershell
python scripts/base_threshold_scan.py <新的功率输入扫描配置.yaml>
```

历史配置只处理上述主要覆盖景，扫描Q30/40/50/60/70/80/90。清空`scene_ids: []`可处理所选日期的所有已完成场景；也可修改日期和分位数。改变参数时使用新的输出及缓存目录。

原滤波、地形掩膜和成果只读；不会重复SNAP或几何计算。每景一次计算所需分位数，各Q分组执行分割和面清理。阶段进度在本实验`data_cache`中；中断后使用相同配置重跑。

输出目录：`E:/InSAR/水体提取/北京密云区/outputs/base_threshold_scan_20261113`。

- `base_q*/日期/景号/`：`water_polygon.shp/tif`、参数、质量JSON和快视图。
- `figures/景号.png`：同一视野的SAR及各Q最终结果叠加图。
- `comparison.csv`：精确幅度阈值、有效面积、原始候选面积、辅助修正后面积和面清理后像元数。面积与像元数不混用。
- `processing.log`、`stage_timings.csv`：逐景、逐Q进度和阶段耗时。

先观察水库恢复与陆地扩张能否同时接受，再与Otsu对照。若较低Q持续漏水、较高Q大量提取陆地，说明该景水陆幅度重叠，单一全局阈值不足；需进一步检验局部自适应阈值或受约束的水域恢复。没有同期人工核验结果时不报告Recall或精度改善。
