# 水体分割损失函数：概念、公式与本项目的实验路径

更新日期：2026-10-26。

这份说明从当前双极化 SAR 水体分割任务出发，解释损失函数在优化什么，以及为什么“换一个损失”不等于“提高识别能力”。阅读时可以先看每节的直观解释，再看公式。

本文对应 [损失实现](../src/supervised/models/losses.py)、[统一训练入口](../src/supervised/train.py) 和 [PVT/UAFNet 模型](../src/supervised/models/pvt.py)。本项目目前已实现的单头损失只有 `ce`、`bce`、`bce_dice`；其他方法是科普和后续候选，不代表已经接入训练。

## 1. 损失函数在训练过程中做什么

一次训练迭代可以理解为：

```text
VV/VH 影像 → 网络 → logits → 与人工标签比较 → 得到损失
                       ↑                       ↓
                       └──── 参数更新 ← 反向传播
```

损失函数把预测与标签的差异转换成一个可求导的标量。优化器沿着梯度调整参数，希望下一次预测更符合标签。

损失不是最终评价指标。BCE 衡量逐像素的概率预测误差，而 F1、IoU 通常基于阈值化后的分割结果。损失下降、Recall 上升，都不自动意味着 F1 或相同 Precision 下的 Recall 改善。

损失函数也不能补出输入中缺少的信息。例如，水体与山体阴影具有相似 SAR 强度时，提高水体权重可能同时增加两者的水体预测；要提高区分能力，还需要有效的上下文、特征或辅助观测。

## 2. 先明确 logits、概率、标签和有效像素

当前 UAFNet 的一个输出头是 `[B, 1, H, W]`，标签是 `[B, H, W]`。`B` 是批量大小，单输出通道表示水体的 logit，而不是已经阈值化的水体掩膜。

| 符号或数值 | 含义 |
|---|---|
| `z`，logit | 网络输出的实数，可为负数、零或正数 |
| `p = sigmoid(z)` | 对应的水体概率表达，范围为 0～1 |
| `y = 1` | 有效水体标签 |
| `y = 0` | 有效非水体标签 |
| `y = -1` | 本项目内部的忽略标记 `IGNORE_INDEX`，不参与损失和指标 |

Sigmoid 的定义为：

\[
p=\sigma(z)=\frac{1}{1+\exp(-z)}
\]

例如 `z=0` 时 `p=0.5`，`z≈2.197` 时 `p≈0.9`。当前采用 `p>=0.5`，因此 logit 大于或等于零对应预测水体。

“输出叫概率”不代表它已经正确标定。模型给出 `p=0.9` 的一组像素，未必真的有 90% 是水体，这需要单独评价。

本项目读取器会把影像或标签文件掩膜无效的位置写为 `-1`。损失中的 `valid = label != -1` 依赖已经检查过的标签编码为 0/1；这个表达式本身不是通用标签合法性检查。有效的 0 是背景，不能因为数值为 0 就忽略。

## 3. BCE：逐个像素判断水体概率是否合理

Binary Cross Entropy，二元交叉熵，分别惩罚“真水体的概率太低”和“真背景的水体概率太高”。单像素形式为：

\[
\ell_{\mathrm{BCE}}(p,y)
=-y\log p-(1-y)\log(1-p)
\]

| 标签 | 水体概率 | BCE，约值 | 直观含义 |
|---|---:|---:|---|
| 水体，1 | 0.9 | 0.105 | 预测较好 |
| 水体，1 | 0.1 | 2.303 | 自信地漏检，惩罚较大 |
| 背景，0 | 0.1 | 0.105 | 预测较好 |
| 背景，0 | 0.9 | 2.303 | 自信地误检，惩罚较大 |

本项目使用 `binary_cross_entropy_with_logits`，直接输入 logits。库函数在内部稳定地完成 Sigmoid 与交叉熵计算；不要在调用它之前再做一次 Sigmoid。[PyTorch 官方说明](https://docs.pytorch.org/docs/stable/generated/torch.nn.BCEWithLogitsLoss.html)

对于有效像素集合 \(\Omega\)，当前单头 BCE 是：

\[
L_{\mathrm{BCE}}=\frac{1}{|\Omega|}
\sum_{j\in\Omega}\ell_{\mathrm{BCE}}(p_j,y_j)
\]

这里的 \(\Omega\) 覆盖整个 batch 的有效像素，因此有效像素更多的图片贡献更大。它不是“每张图先求平均，再对图片等权平均”；只有每张图有效像素数相同时，两种计算才等价。

BCE 的优点是目标直接、梯度清楚，适合作为稳定基线。它的限制是普通均值按像素计数，大片背景的总贡献可能较大，而小水体没有自动获得额外关注。

### 加权 BCE 又改变了什么

若只增加正类系数 \(w_+\)，公式变为：

\[
\ell=-w_+y\log p-(1-y)\log(1-p)
\]

增加 \(w_+\) 会提高水体像素的错误代价，常使模型更愿意预测水体；这可能减少漏检，也可能增加误检。它不等价于增加更多真实水体场景，也不保证相同 Precision 下的 Recall 提高。

当前项目的 `bce` 没有设置这个正类权重。`BCE_WEIGHT` 则是 `bce_dice` 组合中的整项系数，两者不要混淆。

## 4. CE：用两个通道表达互斥的水体与背景

Cross Entropy，交叉熵，是多类别互斥分类的常用损失。当前历史双类别模型输出 `[B, 2, H, W]`，两个通道分别是背景和水体 logits，CE 根据标签选择正确类别并计算负对数概率。

设背景 logit 为 \(z_0\)，水体 logit 为 \(z_1\)，则：

\[
p_1=\frac{e^{z_1}}{e^{z_0}+e^{z_1}}
=\sigma(z_1-z_0)
\]

因此，在标签、权重与平均方式一致时，双通道 CE 的数据损失等价于以 \(z=z_1-z_0\) 为单 logit 的 BCE。二分类使用 BCE 或 CE，并不天然决定哪一个更准确。

两个实现的网络参数化不同，所以不能据此保证实际训练轨迹、正则化效果完全相同。本项目沿用历史模型的 CE 与单通道 UAFNet 的 BCE，避免为改损失同时修改输出头。

## 5. Dice：衡量整片水体是否重叠

Dice 更关心预测水体与真值水体的整体重叠。对于二值预测，它等价于同一统计范围内水体类别的 F1：

\[
\mathrm{Dice}=\frac{2TP}{2TP+FP+FN}
\]

训练时不能先把概率按 0.5 变成 0/1，否则阈值操作无法提供正常的反向传播。Soft Dice 使用连续概率：

\[
L_{\mathrm{Dice}}=1-
\frac{2\sum_{j\in\Omega}p_jy_j+s}
{\sum_{j\in\Omega}p_j+\sum_{j\in\Omega}y_j+s}
\]

这里采用与本项目一致的线性分母形式，平滑量 `s=1`。其他代码也可能使用平方分母或不同平滑量，同名 Dice 并不保证实现相同。

例如，忽略平滑量时，一幅图有 100 个真水体像素，预测 100 个，其中 80 个重叠，则 Dice 为 0.8。Dice 把误检与漏检放入同一个区域比例，不是逐像素交叉熵。

当前 `bce_dice` 为：

\[
L=\texttt{BCE\_WEIGHT}\cdot L_{\mathrm{BCE}}
+\texttt{DICE\_WEIGHT}\cdot L_{\mathrm{Dice}}
\]

其中 Dice 按每张图分别计算，再对至少有一个有效像素的图求平均。这样一幅小水体图和一幅大水体图的 Dice 项可以有相同图片权重，而批量全局 Dice 会更受大水体图影响。

### 没有水体的图怎么办

如果有效标签全为背景，\(\sum y=0\)，当前 Dice 损失为：

\[
L_{\mathrm{Dice}}=1-\frac{1}{\sum p+1}
\]

预测概率全部接近零时损失接近零；存在水体概率时会受到惩罚。但是在大图上累积很多很小的概率，也可能让该项接近 1，梯度行为与 BCE 不同。因此无水图仍有价值，不应简单删除，也不能认为加 Dice 后可以不保留背景监督。

## 6. Soft IoU：直接约束交集与并集

IoU，也叫 Jaccard Index，是交集除以并集：

\[
\mathrm{IoU}=\frac{TP}{TP+FP+FN}
\]

训练中的一种 Soft IoU 损失为：

\[
L_{\mathrm{IoU}}=1-
\frac{\sum py+s}{\sum p+\sum y-\sum py+s}
\]

上面 100 个真水体、100 个预测水体、80 个重叠的例子中，IoU 为 \(80/120≈0.667\)。Dice 与 IoU 都关注区域重叠，但梯度和组合尺度不完全相同。

对同一组二值混淆计数，\(F1=2IoU/(1+IoU)\)，二者是单调关系；对逐图平均或带平滑的软损失，不应直接套这个关系推断优化结果。

本项目尚未实现独立 Soft IoU。后续候选是“只在最终头 BCE 上增加小权重区域项”，并单独对照，而不是让四个头同时换目标。

## 7. Lovasz：用可优化的代理目标接近 IoU

硬 IoU 包含阈值和离散集合操作，不能直接作为常规可导损失。Lovasz 系列根据预测错误排序，对 IoU 对应的集合损失构造可优化的代理形式。

它不等于上面的 `1 - soft IoU`。排序使每个像素的权重还与当前整组错误分布相关。

当前单通道水体 logits 对应的候选是 **Lovasz hinge**；多类别概率对应 **Lovasz-Softmax**。输入形式不同，不能只把函数名替换进现有 BCE 调用。按图计算还是把整个 batch 展平，也会改变目标。

可测试 BCE 与 Lovasz 的组合，但没有证据保证它一定优于现有基线。本项目目前未接入。[作者论文与官方实现](https://github.com/bermanmaxim/LovaszSoftmax)

## 8. Tversky：显式调整误检和漏检的相对代价

Tversky 把 Dice 中对称的错误代价改为可调整形式。本文统一约定 **alpha 对应 FP，beta 对应 FN**：

\[
T=\frac{TP+s}{TP+\alpha FP+\beta FN+s},\qquad L_T=1-T
\]

训练时使用软计数：\(TP=\sum py\)、\(FP=\sum p(1-y)\)、\(FN=\sum(1-p)y\)。

当 \(\alpha=\beta=0.5\) 且忽略平滑差异时，它对应 Dice。提高 beta，就是提高漏检项的相对代价。例如 `alpha=0.3, beta=0.7` 更偏向减少漏检，代价可能是误检增加。

不同论文和库可能交换 alpha、beta 的命名。使用之前一定先看哪一个系数实际乘在 FP 或 FN 上，不能只复制两个数字。

它适合显式表达业务对错误的偏好，不代表提高了所有工作点的区分能力。原论文主要验证医学分割，本项目尚未接入。[Tversky 原论文](https://arxiv.org/abs/1706.05721)

## 9. Focal：减少容易像素的贡献

Focal Loss 在交叉熵上增加一个随难度变化的系数：

\[
p_t=\begin{cases}p,&y=1\\1-p,&y=0\end{cases},\qquad
L_F=-\alpha_t(1-p_t)^\gamma\log p_t
\]

当 `gamma=2` 时：正确类别概率 0.9 的容易像素，其调制系数为 0.01；正确类别概率 0.2 的困难像素，系数为 0.64。因此它让容易像素的损失下降得更多。`alpha_t` 可另外控制类别权重；`gamma=0` 时退化为带相应类别权重的交叉熵。

本项目已经使用按整幅图 BCE 评分的困难采样。Focal 则主要在像素级调整贡献，两者不是相同操作，但同时使用可能进一步放大困难像素或错误标签。首次损失对照不应一并修改采样规则。

Focal 最初用于密集目标检测，不能仅凭该任务上的成功就认定它能改善 SAR 水体。本项目尚未接入。[Focal Loss 原论文](https://arxiv.org/abs/1708.02002)

## 10. 结构与边界损失：关注哪里错，以及边界错多远

### DAD 代码中的结构损失

DAD 的公开训练代码使用局部标签变化生成权重，再组合加权 BCE 与加权 IoU：

\[
w_j=1+5\left|\operatorname{AvgPool}_{31\times31}(y)_j-y_j\right|
\]

大块水体或背景内部的邻域标签比较一致，权重接近 1；岸线、小目标附近邻域混合，权重可能更大。因此它强调局部结构，而不是只增加所有水体像素的代价。代码将此形式注明为参考 F3Net，不能把该公式本身视作 DAD 独创。

用于本项目时，需要让局部统计正确排除无效像素，并单独验证窗口尺寸和系数。直接把 `-1` 送入均值池化会污染权重；标签错位也可能被放大。[DAD 官方结构损失实现](https://github.com/Henryjiepanli/DAD/blob/main/train.py)

### 距离型边界损失

另一类方法根据标签边界的距离场，约束预测轮廓偏移。它提供的信息与区域面积重叠不同，通常与 BCE 或 Dice 组合，而不是独立替代所有区域监督。Boundary Loss 的原始实验主要是医学分割，本项目未实现。[Boundary Loss 原论文](https://proceedings.mlr.press/v102/kervadec19a.html)

用户提出的边界缓冲区采样指标属于**评价方法**；只有把相应目标写成可求导表达并加入训练，它才成为训练损失。边界指标改善也应同时检查整片漏检、远离边界的误检，避免只看窄带。

## 11. 特征对比损失：让水体与相似背景更可分

BCE 直接约束输出概率；特征对比损失约束中间表示，希望适当选择的同类特征更接近、异类特征更可分。

对 SAR 水体，目标可以是区分水体与暗背景，但“暗”本身不能决定负样本标签。需要可靠的正负样本、采样位置与特征层选择。

这不是替换一个公式即可完成的改动，通常还涉及特征投影、对比样本构造以及额外系数。标签不可靠时也会把错误关系写入特征空间。它属于后续研究方向，当前未实现。

## 12. 损失尺度、空图和平均方式为何会影响结果

| 实现选择 | 对训练的影响 |
|---|---|
| 对所有有效像素求均值 | 有效像素更多的图贡献更大；当前 BCE 如此 |
| 每张图算损失再平均 | 各图贡献更接近等权；当前 Dice 如此 |
| 整个 batch 算一次 Dice | 大水体图更容易支配区域重叠统计 |
| 四个头求和或求平均 | 相对头权重相同，但总损失及梯度尺度不同 |
| 损失组合系数为 1:1 | 只表示数值相加，不代表梯度贡献相同 |
| 全部像素无效 | 当前返回连着计算图的零损失，不伪造背景标签 |

输入均值/标准差归一化与损失归一化是不同概念：前者处理 SAR 输入的数值尺度，后者决定误差如何聚合。损失通常处理 logits 和标签，不对 0/1 标签做均值标准差标准化。

比较两个实验时，不能直接拿一个 BCE 值与一个 BCE+Dice 值判断优劣。即使系数总和相同，也不能保证梯度大小完全相同；应看相同评价口径下的结果。

## 13. UAFNet 的四头深监督与不同“权重”

当前模型依次返回四个已上采样到输入尺寸的 logits：

| 输出顺序 | 模型中的名称 | 作用 |
|---:|---|---|
| 0 | `coarse_full` | FPN/粗解码器的初始预测 |
| 1 | `prediction4` | 第一级 UAFM 输出 |
| 2 | `prediction3` | 第二级 UAFM 输出 |
| 3 | `prediction2`，最终输出 | 第三级 UAFM 输出；残差模式下为粗 logits 加修正 logits |

每个头都与同一份标签比较，这称为深监督。它能给中间层提供直接学习信号，但辅助头需要多大权重属于实验问题。

四个头不是四个独立模型。最终头的梯度还会沿共享特征、残差连接等路径传回前面的模块；提高最终头权重不会只更新最后一层。

| 权重类型 | 决定什么 | 当前状态 |
|---|---|---|
| 深监督头权重 | 哪个输出头的损失贡献更大 | 本轮调整 |
| 采样权重 | 哪幅图出现得更多 | 保持全局困难采样规则 |
| 类别/像素权重 | 哪类像素、哪些位置的错误代价更大 | 本轮仍普通 BCE |
| 场景损失权重 | 某类场景整图误差的影响多大 | 本轮未加入 |
| UAFM 内部等级权重 | 特征融合怎样使用前景/背景概率 | 保留现有结构 |

UAFM 的等级权重由概率生成，并使用 `detach()`。这表示梯度不经过等级生成操作，但更换损失仍会在后续训练中改变概率分布，间接改变特征融合行为。

因此，未来尝试区域损失时，可以先只给最终头增加小权重区域项，保留前面各头 BCE，便于观察概率表达和最终分割的变化。普通 BCE 也不保证概率自动正确标定，仍需实测。

## 14. 已完成的实验：只改变四头监督权重（2026-10-26）

比较基线固定为“全局困难采样 + 最终残差 + BCE”，不使用上一次的混合少水体困难池作为控制组。

原始等权目标：

\[
L_{\mathrm{old}}=L_c+L_4+L_3+L_f
\]

本轮目标：

\[
L_{\mathrm{new}}=L_c+0.5L_4+0.5L_3+2L_f
\]

四个 \(L\) 都仍是普通有效像素 BCE。保留粗预测监督，降低两个中间头的相对权重，提高最终输出的相对权重；系数总和仍为 4，但不保证梯度范数与原实验相同。

`train.py` 对应配置：

```python
METHOD = "uafnet"
UAFNET_FINAL_RESIDUAL = True
LOSS_NAME = "bce"
SAMPLING = "hard"
HEAD_LOSS_WEIGHTS = (1.0, 0.5, 0.5, 2.0)
UAFNET_MBDC_DILATIONS = None  # 复跑此实验时恢复原固定空洞率。
```

权重顺序固定为“粗预测、第一级 UAFM、第二级 UAFM、最终预测”，不按分辨率或变量名数字重新排序。

模型、数据划分、输入波段、已有增强、学习率、训练轮数、困难池比例等沿用控制基线。验证仍评价最终输出，验证损失为未乘头权重的最终头 BCE；困难样本评分也仍是逐图最终头 BCE。虽然评分规则不变，模型更新后分数和困难池成员可能随训练自然变化，不是冻结全部抽样序列。

默认输出保存到新的时间戳目录：

```text
outputs/pvt_uafnet_hard_sampling_residual_head_weights/<时间戳>/
```

与之前实验目录分开，因此不用删除旧结果。检查点记录 `head_loss_weights`；`best.pth` 仍按最低最终头验证 BCE 保存，`best_f1.pth` 仍按最高最终头验证 F1 保存。头权重配置在统一入口中仅对 `uafnet` 生效。

复跑原始等权残差基线时，先设 `UAFNET_MBDC_DILATIONS=None`，保持 `SAMPLING="hard"` 和残差开关，只把 `HEAD_LOSS_WEIGHTS` 改成 `(1.0, 1.0, 1.0, 1.0)`，即可回到 `outputs/pvt_uafnet_hard_sampling_residual/<时间戳>/`。复跑其他历史 UAFNet 方案也需恢复全1头权重，并按原方案设置采样、损失与残差。

在仓库根目录执行：

```powershell
conda activate sar-water
python src/supervised/train.py
```

该实验已完成：固定验证集的最终头 F1 为83.1578%，相对等权基线83.0543%增加0.1035个百分点，但 Recall 从80.4098%降至79.2793%，少水体组也未改善。2026-10-27按用户要求优先开展尺度 MBDC 结构实验，恢复等权 BCE；详见 README 开头。

## 15. 后续顺序及如何判断收益

以下是原定损失/增强顺序；当前按用户要求先独立测试尺度 MBDC，区域损失与裁剪增强仍待实施。

| 顺序 | 对照内容 | 当前状态 |
|---:|---|---|
| 1 | BCE 不变，只调整四头监督权重 | 已完成；F1微升、Recall下降，尚无稳定收益结论 |
| 2 | 独立测试最终头 BCE 加小权重区域项 | 待实现，不与第 1 项同时修改 |
| 3 | 温和裁剪缩放增强 | 待实现，作为独立分支 |
| 4 | 可靠边界错误集中时，测试结构/边界损失 | 待前面结果与标签检查支持 |
| 5 | 整片混淆仍明显时，研究特征对比或结构改进 | 后续研究 |

每次比较固定验证集和指标计算方式。先看未后处理的最终输出 F1、Precision、Recall，再做相同范围阈值扫描，比较相同 Precision 下的 Recall，并查看分场景误差、固定样本和边界质量。

本轮还需要对照粗预测和最终预测：如果最终头 F1 提高，但粗预测也同步提高，而两者差距仍接近零，不能据此断言细化分支已产生独立收益。

训练总 loss 因权重定义变化而改变，不能仅凭它更低判断改良；也不根据验证个案直接反复调出大量权重组合，再把该验证集当作独立测试集。小幅收益应通过复跑或后续独立场景验证确认。
